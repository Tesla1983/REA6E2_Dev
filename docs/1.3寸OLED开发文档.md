## 1. 速览

| 项 | 值 |
| --- | --- |
| 屏 | 1.3 寸单色 OLED，128 × 64，**只用 4 行 × 16 字符**（8×16 字模） |
| 控制芯片 | **SH1106**（固定型号，规格见 §3） |
| 接口 | I2C（IIC0），**P408 = SCL（SCL0_B），P206 = SDA（SDA0_C）**（开漏，非推挽） |
| 接线变更 | **2026-10-23：SDA 由 P407 迁到 P206**，P407 让给 `USB_VBUS`（见 §2.3 / §2.4） |
| 从机地址 | **0x3C**（7 位，SA0 = 0） |
| 总线速率 | **400 kHz**（`I2C_MASTER_RATE_FAST`，实测 398 406 Hz） |
| FSP 驱动 | `r_iic_b_master`，实例名沿用例程叫 `I2C_BH1750`（名字是历史包袱，别改） |

## 2. 硬件与接线

### 2.1 引脚

| 信号 | 引脚 | 数据手册复用名 | 说明 |
| --- | --- | --- | --- |
| SCL | **P408** | `SCL0_B` | 一直没动过 |
| SDA | **P206** | `SDA0_C` | **2026-10-23 由 P407 迁来**；P407 让给 `USB_VBUS` |

| 其它参数 | 值 |
| --- | --- |
| 引脚复用来源 | `projects/ra6e2_66_app/ra_gen/pin_data.c` → `IOPORT_PERIPHERAL_IIC` |
| 上拉 | 模块板自带（**阻值未实测**；400 kHz 下若 `i2c_err` 持续增长，按 §11 处理） |
| 供电 | 3.3 V，与 MCU 同电平，无需电平转换 |

> ⚠ **旧文档 / 旧回忆里的 "P407 = SCL，P408 = SDA" 是错的，两个都错。**
> 数据手册 QFN48 引脚表原文：`P407 = SDA0_B/SSIBCK0_A/USB_VBUS`、`P408 = SCL0_B`。
> 即 P407 本来就是 **SDA**、P408 本来就是 **SCL**，旧文档把方向写反了。
> 这个错误曾让 `bsp_i2c.c` 的总线恢复序列一直拉错脚、形同虚设，已于 2026-10-23 一并修掉。

### 2.2 实际怎么接（照着插线即可）

OLED 模块是标准 4 针 I2C 排针，对到地奇星 RA6E2 板上引出的排针：

| OLED 模块针脚 | 接到板上 | 备注 |
| --- | --- | --- |
| `GND` | GND | 共地，必须接 |
| `VCC` | 3.3V | **不要接 5V**（模块虽有稳压，与 MCU 同电平最稳） |
| `SCL` | **P408** | 板上丝印标 `SCL0` 的那个位置 |
| `SDA` | **P206** | 板上丝印标 `SDA0` 的那个位置 |

**只有 4 根线，不需要上拉电阻**（模块自带上拉）、不需要电平转换、不需要额外的复位或片选。

> 板上实际引出 31 个引脚，其中能凑成同一路 IIC0 的只有
> `P408(SCL0_B)` + `P206(SDA0_C)` 这一组（`P410/P411` 板上**没有引出**，别去试）。

### 2.3 为什么最终是 P408 + P206

这里有两层原因，第二层是 2026-10-23 才踩出来的。

**第一层：底稿是官方 BH1750 例程。**
当前 FSP 根（`projects/ra6e2_66_app`）取自 FSP 的 BH1750 示例工程，
它默认把 `r_iic_b_master` 配在 P407/P408。所以最初"不加任何配置就能用 I2C"是刻意的，不是巧合。

**第二层：P407 是 RA6E2 唯一的 USB VBUS 检测脚。**
数据手册引脚表写明 `P407 = SDA0_B / SSIBCK0_A / **USB_VBUS**` ——
RA6E2 **没有**独立的 USBVBUS 专用引脚，VBUS 检测只能走 P407。

而 PFS 里一个脚只能选一个复用功能：P407 一旦选成 IIC0 的 SDA0，
USB 模块的 VBUS 输入就被**物理切断** ⇒ `INTSTS0.VBSTS` 恒 0 ⇒ 控制器判"无 VBUS"进挂起
⇒ USB 设备枚举永远停在 Default 态（Windows 报"设备描述符请求失败 / 错误43"）。

⇒ 结论：**P407 必须在 I2C 和 USB_VBUS 之间二选一**。本项目要 USB CDC 虚拟串口，
所以把 I2C 的 SDA 挪到同一路的另一根可用脚 **P206（SDA0_C）**，SCL 保持 P408 不动。
**硬件上只改一根线**（SDA 从 P407 换到 P206）。

`ra_gen/pin_data.c` 里对应的一句是 `IOPORT_PERIPHERAL_IIC`（PSEL 由引脚自身决定，
和 `IOPORT_PERIPHERAL_USB_FS` 能在 P814/P815 上同时选 USB_DP / USB_DM 是同一机制）。

### 2.4 接线变更记录与验证

**变更（2026-10-23）**

| 引脚 | 变更前 | 变更后 | 用途 |
| --- | --- | --- | --- |
| `P408` | IIC0 `SCL0_B` | **不变** | OLED SCL |
| `P206` | 空闲（原 SPI0_MISO，屏只写不读，未用） | **IIC0 `SDA0_C`** | OLED SDA |
| `P407` | IIC0 `SDA0_B` | **`USB_FS`（USB_VBUS）** | USB 设备 VBUS 检测 |

改了哪些文件：

- `projects/ra6e2_66_app/ra_gen/pin_data.c`：`BSP_IO_PORT_04_PIN_07` → **`BSP_IO_PORT_02_PIN_06`**
- `projects/ra6e2_66_app/configuration.xml`：`i3c_fslash_iic.sda0.p407` → `p206`
  （⚠ **故意没有跑 RASC 重生成** —— 该工程的 `bsp_clock_cfg.h` 里 PLL 源是手改过的，
  重生成会覆盖回 `MAIN_OSC`，可能导致卡在等外部晶振。见 `RASC开发文档.md`）
- `src/i2c/bsp_i2c.c/.h`：`I2C_RECOVER_SCL_PIN = P408`、`I2C_RECOVER_SDA_PIN = P206`

**寄存器级验证（`probe-rs` 直读 PFS）**

PFS 基址是 **`0x40080800`**（不是 `0x40040000`）；`PmnPFS = base + m*0x40 + n*4`。

| 引脚 | 地址 | PFS 值 | 解析 |
| --- | --- | --- | --- |
| `P206` | `0x40080898` | `0x07010000` | PSEL=0x07 → **IIC0** ✓ |
| `P408` | `0x40080920` | `0x07010002` | PSEL=0x07 → **IIC0** ✓ |
| `P407` | `0x4008091C` | `0x13010002` | PSEL=0x13 → **USB_FS** ✓ |

**功能级验证（改线后复位，读固件全局量）**

| 量 | 实测值 | 含义 |
| --- | --- | --- |
| `g_oled_addr` | `0x3C` | 扫描到 OLED |
| `g_oled_init_err` | `0` | 初始化成功 |
| `g_oled_xfer_err` | `0` | 无传输错误 |
| `g_oled_frames` / `g_oled_pages_flushed` | 持续增长 | 正常刷新中 |
| `g_i2c_err_count` / `g_i2c_bus_stuck` | `0` / `0` | 总线健康 |

同时 `g_usb_vbsts = 1`、`g_usb_cfg_cnt = 1` ⇒ **I2C（OLED）与 USB CDC 可以同时工作**，
这是本次迁移的最终目的。

## 3. 控制芯片：SH1106

**这块屏的控制芯片就是 SH1106。驱动一律按本节规格写。**

### 3.1 规格

| 项 | 值 |
| --- | --- |
| 芯片 | **SH1106**（I2C 接口，只写，不支持读） |
| 从机地址 | 0x3C（7 位，SA0 = 0） |
| GDDRAM | **132 列 × 8 页**，可见 128 列居中 ⇒ **列偏移 = 2** |
| 寻址方式 | **只有页寻址**：`0xB0 + 页号` + `0x00` / `0x10` 设列，然后连续写本页数据 |
| 列指针行为 | 只在**页内**递增，到本页末回卷本页列 0，**不跨页** |
| 电荷泵 | **`0xAD 0x8B`**（DC-DC 开）+ **`0x33`**（设 VPP） |
| 对比度 | `0x81` + 值 |
| 显示开关 / 正反显 / 全点 / 段方向 | `0xAF`/`0xAE`、`0xA6`/`0xA7`、`0xA4`/`0xA5`、`0xA1`/`0xA0` |

### 3.2 商家标注

模块丝印或商品页若写 `SSD1106` —— 这个型号不存在，是 `SH1106` 的误写。
按 §3.1 的规格处理即可，不做任何识别。

### 3.3 三条硬约束（写驱动时必须守）

1. **电荷泵只能用 `0xAD 0x8B` + `0x33`（设 VPP）**。写 `0x8D` 不会开泵，VPP 不升压，屏不亮。
2. **只能页寻址**：`0x20` / `0x21` / `0x22` 这类寻址/窗口命令本芯片不接收，一律不发。
3. **列指针不跨页**：一页写完必须重设页号与列地址，8 页分 8 次写；不要一次连写 1024 字节。

## 4. 驱动实现

### 4.1 文件清单

```
src/oled/bsp_oled.c      SH1106 驱动：初始化 / 帧缓冲 / 画点 / 画字符 / 画矩形 / 画位图
src/oled/bsp_oled.h      对外接口 + 运行时状态全局变量（注释即规格书）
src/oled/oled_font.h     8x16 ASCII 字库（95 个可打印字符）
src/i2c/bsp_i2c.c/.h     I2C 总线封装：Write / Read / Probe + NACK 重试
src/Apply/app.c          主循环：调用方，只做调度不做细节
```

### 4.2 帧缓冲

1024 字节（128 × 64 / 8），页优先排布：字节下标 = `page * 128 + x`，bit0 = 该页最上面一行。
所有绘制函数只改帧缓冲，**不上总线**；只有 `OLED_Refresh()` 才真正发数据。

### 4.3 页寻址刷新（SH1106 硬约束）

必须分 8 页写，每页三步：

```
0xB0 + 页号  →  0x02 / 0x10 设列起始（含列偏移 2）  →  0x40 + 128 字节数据
```

列偏移做成宏 `OLED_COL_OFFSET`（当前 = 2）。
**核对方法**：信息屏的满屏边框应四边紧贴屏缘；偏 2 像素就把这个宏改成 0 重烧。

**清屏必须在 `0xAF`（开显示）之前做**，否则上电瞬间会闪一下 GDDRAM 里的随机数据。

### 4.4 字库

从官方模块移植库 `1.3寸单色OLED显示屏/.../oledfont.h` 的 `asc2_1608` **机械提取**（不是手写）。
布局是**列优先** —— 每字节 = 竖直 8 像素（bit0 在上），前 8 字节为上半（行 0–7），
后 8 字节为下半（行 8–15），索引 = `ch - 0x20`。

> ⚠ 字库只含 ASCII，**屏上显示不了中文**。所以 `app.c` 里所有上屏文字都是英文，
> 中文说明只写在代码注释里。

### 4.5 I2C 传输重试

一帧要发 16 笔事务（8 次命令 + 8 次数据），密集连发时 SH1106 会偶发 NACK
（错误码 18 = `FSP_ERR_ABORTED`）。`bsp_i2c.c` 里做了 **NACK 自动重试 1 次**并计数
（`g_i2c_err_count` / `g_i2c_retry_count` / `g_i2c_last_err`）。

## 5. 对外接口（`src/oled/bsp_oled.h`）

```c
fsp_err_t OLED_Init  (void);                                   /* 开 I2C → 确认在线 → 初始化序列 → 清屏 → 开显示 */
void      OLED_Clear (void);                                   /* 只清帧缓冲，不上屏 */
void      OLED_Refresh(void);                                  /* 脏页 diff 后上屏 */
void      OLED_DrawPixel (int16_t x, int16_t y, uint8_t on);    /* 越界自动丢弃 */
void      OLED_DrawChar  (int16_t x, int16_t y, char c);        /* (x,y) = 左上角 */
void      OLED_DrawString(int16_t x, int16_t y, const char *p); /* 逐字符裁剪，可整体在屏外 */
void      OLED_DrawRect  (int16_t x0, int16_t y0, int16_t x1, int16_t y1);
void      OLED_DrawBitmap(int16_t x0, int16_t y0, const uint8_t *p_bmp,
                          uint16_t w, uint16_t h, uint16_t stride, uint8_t invert);
```

`OLED_DrawBitmap` 是**不透明贴图**：位图为 0 的像素会把帧缓冲对应点擦掉，不是跳过。
要透明背景得另加 key color 参数，目前没这需求。
它内部不走 `OLED_DrawPixel` 逐点（50×52 = 2600 点，逐点要 2600 次边界判断 + 除法），
而是把页基址与位掩码提到行循环外，每行只算一次，实测省掉约 90% 开销。

### 运行时状态变量（`volatile`，探针可直接读）

| 变量 | 含义 | 健康值 |
| --- | --- | --- |
| `g_oled_addr` | 0x3C = 在线，0 = 没找到 | 0x3C |
| `g_oled_init_err` | 初始化错误码 | 0 |
| `g_oled_xfer_err` | 最后一次传输错误码 | **恒为 0，见 §10** |
| `g_oled_frames` | 已刷新帧数 | 持续增长 |
| `g_oled_pages_flushed` | 累计上屏页数 ÷ frames = `ppf` | 全刷 8.0 / 只刷文字带 2.0 |

## 6. 两个必须存在的回调符号

`ra_gen/hal_data.c` 里写死了两个 `.p_callback`：

```c
.p_callback = BH1750_callback,   /* I2C 主机传输回调 → src/i2c/bsp_i2c.c */
.p_callback = uart0_callback,    /* SCI0 UART 回调   → src/hal_callbacks.c */
```

平时因为 `--gc-sections` 把没人引用的 `hal_data.o` 丢掉了，不定义也不报错；
**一旦代码引用了 I2C 句柄，`hal_data.o` 就会参与链接，这两个符号必须存在**，
否则报 `undefined reference to BH1750_callback` / `uart0_callback`。

名字沿用官方 BH1750 示例的模块名，不是本工程起的（所以看着别扭，但不能改）。

`BH1750_callback` 承担实际功能（置传输完成标志），不是空壳；
`uart0_callback` 本工程不用串口，只是满足链接的存根。

## 7. 应用层行为（`src/Apply/app.c`）

当前上电流程：

1. `OLED_Init()` —— 开 I2C、确认 0x3C 在线、发 SH1106 初始化序列（逐条对齐官方 `oled.c`）
2. **信息屏 2 秒** —— 满屏边框 + `ADDR 0x3C` / `IC SH1106` / `COL+2 128x64`（验证列偏移用）
3. **位图屏 2 秒** —— `xjp` 50×52 位图居中
4. **TSN 温度屏（常驻）** —— 每秒读一次片上温度传感器，显示
   `RA6E2 JUNCTION T` / `T=38.6 C` / `TSN->ADC12(-3)`

> 停留时间原本 5 s + 3 s，改成 2 s + 2 s：原来复位后 8 秒屏幕上一直是静态画面，
> 看着跟"按了 RST 卡死"没区别。

找不到 OLED 时：板载 LED（**P402，低电平点亮**）快闪 150 ms 报错，不做任何显示操作。

正常时的 LED 心跳：当前温度屏循环里**每秒翻转一次**（`tsn_tick % 2`，≈ 0.5 Hz）。
跑马灯时期是按帧数翻转，60 帧一次 ≈ 1 Hz —— 原先是 5 帧，帧率优化后不改就会变成 20 Hz 频闪。
换显示内容时记得同步改心跳节奏，别让"看起来正常"变成"闪得像故障"。

> 历史：温度屏之前是 `helloworld` 跑马灯（`MARQUEE_*` 宏还留着），
> §8 的帧率数据就是在跑马灯上测的 —— 跑马灯每帧内容都在变，最能压出带宽上限。

## 8. 帧率优化：9 fps → 164 fps（2026-10-05 已实施并目视验收）

### 8.1 结论

| 指标 | 优化前 | 优化后 | 倍数 |
| --- | --- | --- | --- |
| 帧率 | 9.3 fps | **150 ~ 164 fps** | ≈ 17× |
| 每帧耗时 | 108 ms | 约 6 ~ 7 ms | ≈ 1/16 |
| 每帧 I2C 数据量 | 1064 字节 | 266 字节 | 1/4 |
| `ppf`（平均每帧刷几页） | 8.0（全刷） | **2.00** | 1/4 |
| I2C 总线速率 | 99.8 kHz | **398.4 kHz** | 4× |
| RAM 占用 | 8.9 KB（22%） | 11.9 KB（29.6%） | +3 KB |

改动集中在三个文件：`src/oled/bsp_oled.c`、`src/i2c/bsp_i2c.c`、`src/Apply/app.c`，
外加一份配置变更（`configuration.xml` → RASC 重新生成 `ra_gen/`）。

### 8.2 瓶颈在哪：先把 108 ms 拆开

优化前每帧固定发 8 页，每页一次「设页号+列地址」命令 + 一次 128 字节数据：

```
每页:  4 字节命令(0x00 + 页地址 + 列低 + 列高)  +  129 字节数据(0x40 + 128)
8 页:  32 + 1032 = 1064 字节
```

I2C 每字节 9 bit（8 数据 + 1 ACK），在 99.8 kHz 下：

| 构成 | 耗时 | 占比 |
| --- | --- | --- |
| I2C 位时间（1064 × 9 bit / 99.8 kHz） | 96.0 ms | **89%** |
| `i2c_wait_done()` 的 1 ms 轮询粒度浪费（16 笔 × 0.5 ms） | 8.0 ms | 7% |
| 事务头（16 × START+地址+STOP） | 1.8 ms | 1.5% |
| `OLED_Clear()` + 逐像素绘制 | < 1 ms | < 1% |
| **合计** | **≈ 107.8 ms** | — |

建模值与实测 108 ms 吻合。**结论：瓶颈是总线波特率，不是 CPU，也不是绘制代码。**
所以「优化绘制函数」这类方向收益接近于零，别往那儿使劲。

### 8.3 三个优化手段与各自收益

| 手段 | 单独收益 | 风险 | 说明 |
| --- | --- | --- | --- |
| ① **脏页刷新** | 108 → 27 ms（37 fps） | 无（纯软件） | 数据量 ÷4 |
| ② **I2C 100k → 400k** | 108 → 33 ms（30 fps） | 低（实测偶发 NACK，全部被重试兜住） | 位时间 ÷4 |
| ③ **等待轮询 1 ms → 100 µs** | 削掉 8 ms | 无 | 提速后才成为瓶颈 |
| ①+②+③ | **108 → ≈ 7 ms（150+ fps）** | — | 实测值 |

三者正交，可单独启用、单独回退。

### 8.4 脏页刷新 —— 最容易做错的一项

**❌ 错误做法：绘图时标脏。**
直觉方案是「`OLED_DrawPixel` 时把对应页标脏，`Refresh` 只刷脏页」。在本工程**会完全失效**：

```c
while (1) {
    OLED_Clear();        /* ← 每帧全清, 会把 8 页全部标脏 */
    OLED_DrawString(...);
    OLED_Refresh();
}
```

主循环每帧都先 `OLED_Clear()`，标脏法直接退化成全刷，白干。

**✅ 正确做法：影子副本按页 diff。**
多一份 1024 字节的「已上屏内容」副本，刷新时逐页 `memcmp`：

```c
static uint8_t s_fb[1024];      /* 帧缓冲 */
static uint8_t s_shadow[1024];  /* 已上屏内容副本 */
static bool    s_shadow_valid;  /* .bss 初值 false ⇒ 第一帧强制全刷建立基线 */

for (page = 0; page < 8; page++) {
    base = page * 128;
    if (s_shadow_valid && (0 == memcmp(&s_fb[base], &s_shadow[base], 128))) {
        continue;               /* 内容没变, 连命令都不发 */
    }
    /* ...发命令 + 128 字节数据... */
    if (FSP_SUCCESS == err) {
        memcpy(&s_shadow[base], &s_fb[base], 128);   /* 只在成功后同步 */
    }
    g_oled_pages_flushed++;
}
s_shadow_valid = true;
```

两个刻意的设计：

- **发送失败时不更新影子副本** —— 下一帧比对仍不相等，会自动重刷该页，传输出错可自愈。
- **`s_shadow_valid` 用「反逻辑」命名** —— 依赖 `.bss` 初值 `false` 表示「副本不可信」，
  不需要任何显式初始化，也不会漏掉上电第一帧。

代价：RAM +1 KB；每帧 8 次 128 字节 `memcmp`（< 5 µs，可忽略）。

**为什么跑马灯只刷 2 页：** `MARQUEE_Y = 24`、字高 16，占 y = 24..39，
即**页 3 和页 4**。其余 6 页恒为空白，`Clear` 后与影子副本相同，全部跳过。

### 8.5 I2C 100 kHz → 400 kHz —— 必须走 RASC

**⚠ 只改 `hal_data.c` 的 `.rate` 不生效。**
`r_iic_b_master` 用的是 RASC **预计算**的 `p_extend->clock_settings`（`brl/brh/cks` 寄存器值），
不是运行时按 `.rate` 算的。而且 `hal_data.c` 顶部写着 `generated - do not edit`，
下次生成就会被覆盖。

**正确路径：改 `configuration.xml` → RASC 重新生成。**

```xml
<property id="module.driver.i2c_master.rate"
          value="module.driver.i2c_master.rate.rate_fast"/>
```

```bash
cd projects/ra6e2_66_app
"E:/software/Renesas/RAC/eclipse/rascc.exe" --generate \
    --compiler GCC --device R7FA6E2BB configuration.xml
```

生成结果对照：

| 字段 | 100 kHz | 400 kHz |
| --- | --- | --- |
| `.rate` | `I2C_MASTER_RATE_STANDARD` | `I2C_MASTER_RATE_FAST` |
| 实测波特率 | 99 800 Hz | **398 406 Hz**（误差 0.4%） |
| `iic_clock_freq` | 50 MHz | 100 MHz |
| `cks_value` | 1 | 0 |
| `brl / brh` | 244 / 243 | 113 / 112 |

**波特率公式**（反推验证过，改速率时可用来预判生成值）：

```
T_SCL = (BRL + 1 + BRH + 1) / IICφ  +  t_rise + t_fall
```

用 100 kHz 那组验算：`489 / 50 MHz + 240 ns = 10.02 µs → 99.8 kHz` ✓

FSP 可选档位：`100000`(STANDARD) / `400000`(FAST) / `1000000`(FASTPLUS) / `3400000`(HIGHSPEED)。
**SH1106 手册上限是 400 kHz**，1 MHz 属超规格，不推荐。

### 8.6 等待轮询粒度 1 ms → 100 µs

`src/i2c/bsp_i2c.c` 的 `i2c_wait_done()` 原本用 `R_BSP_SoftwareDelay(1, MS)` 轮询完成标志。
传输往往几十 µs 就结束，却要等到下一次 1 ms 查询才被看见，每笔平均浪费 0.5 ms。

改造前每帧 16 笔 = 8 ms，占 108 ms 的 7%；**提速后总时长只剩 7 ms，这 8 ms 会变成主要开销**，
所以它必须和波特率一起改，不能留到最后。

```c
#define I2C_WAIT_TICK_US     (100u)      /* 原为 1 ms */
#define I2C_WAIT_TIMEOUT_US  (200000u)   /* 超时保护保留 200 ms */
```

### 8.7 配套改动（帧率上去后暴露的问题）

帧率从 9 提到 164 后，两处假设失效，必须同步改：

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| LED 心跳 5 帧翻转 | 变成 20 Hz 频闪 | 改 60 帧（≈ 1 Hz） |
| 日志 10 帧一行 | 每秒 11 行刷屏 | 改 60 帧（≈ 0.5 s 一行） |
| RTT 缓冲 1024 B | 启动积压回绕，**行被截断**（`off` 被截成 `of`，两行粘成 `frames=960 offrames=17280`） | 改 4096 B |
| banner 写死 `@100kHz` | 与实际 400 kHz 不符 | 改为现读 `I2C_BH1750_cfg.rate` |

banner 那处值得单独说一句 —— 改成从配置读，以后再改速率文案不会再「说谎」：

```c
#include "hal_data.h"    /* app.c 新增 */
RTT_Printf("FSP 6.6.0 | R7FA6E2BB | I2C P408(SCL)/P206(SDA) @%u kHz\n",
           (unsigned) (I2C_BH1750_cfg.rate / 1000U));
```

## 10. 日志字段怎么读

```
frames=28920 off=12 ppf=2.0 i2c_err=3 retry=3 last=18 xfer=0
```

| 字段 | 变量 | 含义 | 健康值 |
| --- | --- | --- | --- |
| `frames` | `g_oled_frames` | 已刷新帧数 | 持续增长 |
| `off` | `offset` | 跑马灯偏移（px），周期 104，每帧 +2 | 0..102 循环 |
| `ppf` | pages/frames ×10 | **平均每帧刷几页** | 全刷 = 8.0；只刷文字带 = **2.0** |
| `i2c_err` | `g_i2c_err_count` | I2C 累计失败次数 | **看它是否继续增长** |
| `retry` | `g_i2c_retry_count` | 自动重试次数 | 与 `i2c_err` 相等 = 全被重试兜住 |
| `last` | `g_i2c_last_err` | 最后一次错误码 | `18` = `FSP_ERR_ABORTED`（NACK）；`20` = TIMEOUT |
| `xfer` | `g_oled_xfer_err` | OLED 层看到的错误码 | **恒为 0，见下** |

⚠ **`xfer=0` 不代表没出错**：重试发生在 `I2C_Write()` 内部，重试成功就返回 `FSP_SUCCESS`，
OLED 层永远只看到成功。要看真实错误数请认准 `i2c_err`。
（`xfer` 字段目前是冗余/误导的，后续可考虑改成「重试后仍失败」的计数。）

## 11. 风险、判据与回退

### 400 kHz 的已知代价

**会出现持续的低概率 NACK**，实测约 **0.01% ~ 0.03%**（两轮测量：17280 帧累计 22 次；
28920 帧累计 3 次，离散度较大，属随机偶发）。

作为对比：100 kHz 时错误**只在上电阶段出现 8 次，之后 13 万笔事务零错误**。

**判据（关键）：**

```
i2c_err 冻结不涨  =  健康（错误只在启动阶段）
i2c_err 持续增长  =  总线处于临界（信号完整性不足）
```

**为什么可以接受：**

1. `i2c_err == i2c_retry` —— 全部是 ABORTED，且重试一次就成功，无一次最终失败；
2. 脏页 diff 的设计让失败的页下一帧自动重刷（失败时不更新影子副本）；
3. 目视验收通过，屏幕无丢行、无花屏。

**NACK 的待查项：** 模块板 I2C 上拉阻值**未实测**。这类模块常见 10 kΩ，若确实偏大，
400 kHz 下上升沿不足会持续 NACK；可并联 2.2 ~ 4.7 kΩ 上拉到 3.3 V 改善 ——
属硬件改动，动之前先确认模块原理图。

### 回退方法

```bash
# 备份（改之前已存好）
.workbuddy/backup/configuration.20261005_1856.xml
.workbuddy/backup/ra_gen.20261005_1856/

# 回退步骤
cp .workbuddy/backup/configuration.20261005_1856.xml projects/ra6e2_66_app/configuration.xml
cp -r .workbuddy/backup/ra_gen.20261005_1856/* projects/ra6e2_66_app/ra_gen/
./scripts/build.ps1 && ./scripts/flash.ps1
```

只回退波特率、保留脏页优化：帧率约 **37 fps**，错误归零。

## 12. 踩坑清单

| 坑 | 说明 |
| --- | --- |
| 写 `0x8D` 电荷泵 + 水平寻址 | 本芯片不收这两类命令：电荷泵不开（VPP 不升压）、列指针不跨页 → 连写的 1024 字节全堆在页 0，屏上乱闪。按 §3.3 三条硬约束写 |
| 标脏法会失效 | 主循环每帧 `OLED_Clear()` 会全标脏，必须用影子副本 diff |
| 只改 `.rate` 不生效 | `clock_settings` 是 RASC 预计算的寄存器值，必须重新生成 |
| 手改 `hal_data.c` | `generated - do not edit`，且会被下次生成覆盖 |
| 轮询粒度留到最后 | 提速后 8 ms 会变成主要开销，必须和波特率一起改 |
| `ppf` 初期是 2.3 不是 2.0 | 首帧强制全刷被摊进平均值，跑一会儿会收敛到 2.0 |
| 全局变量地址别靠顺序猜 | `retry_count` @ `0x20001598` 低于 `err_count` @ `0x2000159c`，按 `nm` 实际输出读 |
| RTT 缓冲截断 | 1024 B 在 164 fps 下不够，行会被截成半截，改 4096 B |
| banner 写死波特率 | 改配置后文案会说谎，从 `I2C_BH1750_cfg.rate` 现读 |
| `undefined reference to BH1750_callback` | 引用了 I2C 句柄就要求这两个回调符号存在，见 §6 |
| `timeout` 杀不掉 probe-rs | 进程忽略 SIGINT，会一直跑；用 `Get-Process probe-rs \| Stop-Process -Force` |
| `attach` 报 locked up core | 偶发，**重试一次即可**，不是芯片真死 |
| 屏上显示中文 | 字库只有 ASCII，中文必然乱码，见 §4.4 |
| **文档把 SCL/SDA 写反** | 旧文档写 "P407 = SCL，P408 = SDA"，数据手册实际是 `P407 = SDA0_B`、`P408 = SCL0_B`。跟着错的方向写总线恢复序列 ⇒ 一直拉错脚、形同虚设。**引脚的 SCL/SDA 方向一律回数据手册引脚表核对，不要信任何二手文档** |
| **P407 抢了 USB_VBUS** | `P407` 是 RA6E2 **唯一**的 USB VBUS 检测脚，又被 IIC0 的 SDA0 占用 ⇒ `VBSTS` 恒 0 ⇒ USB 枚举停在 Default（Windows "错误43"）。一个脚只能选一个复用功能，**I2C 与 USB_VBUS 在 P407 上互斥**，最终 SDA 迁到 P206，见 §2.3 |
| **`P410/P411` 板上没引出** | 数据手册说它们是 SCL0/SDA0 的可用脚，但地奇星 RA6E2 **没有把它们引到排针**。选脚前先对照板上实际引出的 31 个脚（§2.2 注），别只看数据手册 |

## 13. 还有空间吗

| 方向 | 预估收益 | 评价 |
| --- | --- | --- |
| DTC/DMA 发送（`p_transfer_tx` 目前为 NULL） | 400 kHz 下每字节一次 TXI 中断，中断占比约 40% | 有实际价值，但会牵动 RASC 配置 |
| 命令与数据合并成一笔（repeat-start） | 每帧省 4 次 STOP+START，< 0.5 ms | 收益太小，不值得 |
| 1 MHz（FASTPLUS） | 再 ÷2.5 | **超 SH1106 规格**，不推荐 |
| 减少列地址重发 | 每帧省 16 字节 | 收益 < 2%，且依赖「换页列地址复位」的未验证假设 |

当前的 150+ fps 对这块 128×64 单色屏已远超需求（人眼 30 fps 即流畅），
建议**到此为止**，把带宽余量留给后续要加的显示内容。

> 注：现在常驻的 TSN 温度屏是 1 秒刷一次，带宽几乎不占。
> 帧率余量是留给「串口收上位机数据实时显示」这类场景的（4 行 × 16 字符完全够）。
